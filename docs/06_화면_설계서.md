## 1. 정보구조(IA)

### 1.1 사이트맵 / 화면 계층

App Router의 **라우트 그룹**으로 인증 영역과 보호 영역을 분리한다.
`(auth)`는 미인증 사용자용, `(protected)`는 인증 필수 영역이며 레이아웃 단에서 접근을 통제한다.

```
app/
│
├── (auth)/                         ← 미인증 사용자 그룹 (인증 불필요)
│   ├── login/          page.tsx    [SCR-02] 로그인
│   └── signup/         page.tsx    [SCR-01] 회원가입
│       └── layout.tsx              ← AuthLayout (중앙 정렬 카드, 헤더 없음)
│
├── (protected)/                    ← 인증 필수 그룹 (미인증 시 /login 리다이렉트)
│   ├── layout.tsx                  ← ProtectedLayout (인증 가드 + AppShell/Header)
│   ├── reports/
│   │   ├── page.tsx                [SCR-03] 리포트 목록
│   │   └── [id]/      page.tsx     [SCR-04] 리포트 상세 (동적 라우팅)
│   └── history/        page.tsx    [SCR-05] 조회 이력 (마이페이지)
│
├── layout.tsx                      ← RootLayout (Provider: QueryClient, Zustand 초기화)
└── not-found.tsx                   ← 404 / 잘못된 리포트 ID 폴백
```

### 1.2 접근 통제 흐름 (계층 개요)

```
┌──────────────────────────── RootLayout ────────────────────────────┐
│  QueryClientProvider · Zustand authStore · Toaster                  │
│                                                                     │
│   ┌──────── (auth) ────────┐        ┌──────── (protected) ────────┐ │
│   │  AuthLayout            │        │  ProtectedLayout            │ │
│   │  - 인증된 사용자면      │        │  - 미인증이면 /login 리다이렉트│ │
│   │    /reports 로 이동     │        │  - Header(네비/로그아웃) 노출 │ │
│   │  · 로그인 · 회원가입    │        │  · 목록 · 상세 · 이력        │ │
│   └────────────────────────┘        └─────────────────────────────┘ │
└─────────────────────────────────────────────────────────────────────┘
```

## 2. 화면 목록

| Screen ID | 화면명 | 경로(URL) | 라우트 그룹 | 인증여부 | 설명 |
|---|---|---|---|:---:|---|
| SCR-01 | 회원가입 | `/signup` | (auth) | ✕ | 이메일·비밀번호 기반 가입. 형식·정책 검증, 중복 이메일 처리 |
| SCR-02 | 로그인 | `/login` | (auth) | ✕ | 로그인 → Access(메모리)+Refresh(쿠키) 발급, 성공 시 목록 이동 |
| SCR-03 | 리포트 목록 | `/reports` | (protected) | ✓ | 본인 리포트 서버 페이징·검색·필터·정렬, URL 쿼리 동기화 |
| SCR-04 | 리포트 상세 | `/reports/[id]` | (protected) | ✓ | 점수 게이지·등급 배지·발급정보·민감정보 마스킹, 진입 시 이력 기록 |
| SCR-05 | 조회 이력 | `/history` | (protected) | ✓ | 내 조회 이력 최신순·중복 시점 표시·페이지네이션 |
| SCR-404 | 미발견 | `/*` (폴백) | — | — | 잘못된 경로 / 권한 없는 리포트 ID 접근 시 폴백 |

> 화면 수: **5개**(SCR-01~SCR-05) + 공통 폴백 1(SCR-404).

## 4. 화면별 상세

### SCR-01 · 회원가입 (`/signup`)

**목적**: 이메일 + 비밀번호로 신규 계정을 생성한다. 이메일 형식·비밀번호 정책(8자 이상, 영문/숫자/특수문자 조합)을 클라이언트에서 1차 검증하고 서버 검증과 미러링한다.

**와이어프레임**
```
┌──────────────────────────────────────────┐
│                                          │
│            신용 리포트 서비스              │
│            ─────────────────              │
│              회원가입                      │
│                                          │
│   이메일                                  │
│   ┌────────────────────────────────────┐ │
│   │ you@example.com                    │ │
│   └────────────────────────────────────┘ │
│   ⚠ 올바른 이메일 형식이 아닙니다 (검증 시) │
│                                          │
│   비밀번호                                │
│   ┌────────────────────────────────────┐ │
│   │ ••••••••                       👁  │ │
│   └────────────────────────────────────┘ │
│   · 8자 이상  · 영문/숫자/특수문자 조합   │
│                                          │
│   비밀번호 확인                           │
│   ┌────────────────────────────────────┐ │
│   │ ••••••••                           │ │
│   └────────────────────────────────────┘ │
│                                          │
│   ┌────────────────────────────────────┐ │
│   │            가입하기                 │ │
│   └────────────────────────────────────┘ │
│                                          │
│   이미 계정이 있으신가요? [로그인]         │
└──────────────────────────────────────────┘
```

**인터랙션**
- 실시간 검증: 이메일 형식(zod), 비밀번호 정책, 비밀번호 일치 여부를 blur/change 시 표시.
- 제출 시 `POST /api/auth/signup` 호출. 중복 이메일(409)이면 이메일 필드 하단 에러.
- 가입 성공 → 토스트 노출 후 `/login` 으로 이동.
- 제출 중 버튼 비활성 + 스피너.

**사용 컴포넌트**: `Input`, `Button`, `FormField`(react-hook-form + zod), `PasswordInput`(토글), `Toast`.

**상태**
| 상태 | 처리 |
|---|---|
| 로딩 | 제출 버튼 비활성 + 인라인 스피너 |
| 에러 | 필드 단위 인라인 에러(검증) / 409 중복 이메일 / 5xx 토스트 |
| 빈/초기 | 빈 폼, 버튼 비활성(폼 무효 시) |

### SCR-02 · 로그인 (`/login`)

**목적**: 이메일·비밀번호로 인증한다. 성공 시 Access Token은 메모리(Zustand), Refresh Token은 HttpOnly 쿠키로 보관하고 목록으로 이동한다.

**와이어프레임**
```
┌──────────────────────────────────────────┐
│            신용 리포트 서비스              │
│            ─────────────────              │
│               로그인                       │
│                                          │
│   이메일                                  │
│   ┌────────────────────────────────────┐ │
│   │ test@kcs.co.kr                     │ │
│   └────────────────────────────────────┘ │
│                                          │
│   비밀번호                                │
│   ┌────────────────────────────────────┐ │
│   │ ••••••••                       👁  │ │
│   └────────────────────────────────────┘ │
│                                          │
│   ⚠ 이메일 또는 비밀번호가 올바르지 않습니다 │
│                                          │
│   ┌────────────────────────────────────┐ │
│   │             로그인                  │ │
│   └────────────────────────────────────┘ │
│                                          │
│   계정이 없으신가요? [회원가입]            │
└──────────────────────────────────────────┘
```

**인터랙션**
- 제출 시 `POST /api/auth/login` → 응답 body의 Access를 Zustand에 저장, Refresh는 Set-Cookie로 자동 보관.
- 성공 → `returnUrl`이 있으면 해당 경로, 없으면 `/reports`로 이동.
- 인증 실패(401)는 폼 공통 에러로 표시(어느 필드가 틀렸는지 노출하지 않음 — 보안).

**사용 컴포넌트**: `Input`, `Button`, `FormField`, `PasswordInput`, `Alert`(폼 에러).

**상태**
| 상태 | 처리 |
|---|---|
| 로딩 | 버튼 비활성 + 스피너 |
| 에러 | 401 공통 에러 배너 / 네트워크 오류 토스트 |
| 빈/초기 | 빈 폼 |

### SCR-03 · 리포트 목록 (`/reports`)

**목적**: 본인 신용평가 리포트를 서버 페이징(페이지당 10건)으로 조회한다. 검색(제목/발급기관)·필터(등급, 발급일 기간)·정렬(발급일/신용점수)을 제공하고, 모든 조건을 URL 쿼리 파라미터와 동기화한다. (검색·필터·정렬·페이징은 서버 처리 — 클라이언트 필터링 금지)

**와이어프레임**
```
┌──────────────────────────────────────────────────────────────────────┐
│ [로고]  신용 리포트            리포트목록 | 조회이력        test@.. ▾   │ ← Header
├──────────────────────────────────────────────────────────────────────┤
│  신용평가 리포트 목록                                                   │
│                                                                        │
│  ┌─ 검색·필터 바 ──────────────────────────────────────────────────┐  │
│  │ [🔍 제목·발급기관 검색      ]  등급[전체 ▾]  기간[from]~[to]      │  │
│  │ 정렬[발급일 ▾] [내림차순 ▾]                     [필터 초기화]     │  │
│  └──────────────────────────────────────────────────────────────────┘  │
│                                                                        │
│  ┌──────────────────────────────────────────────────────────────────┐ │
│  │ 제목            │ 발급기관   │ 점수 │ 등급 │ 발급일      │        │ │
│  ├──────────────────────────────────────────────────────────────────┤ │
│  │ 2026 상반기..   │ KCS평가정보 │ 842 │ 🟢2등급│ 2026-05-02 │  [보기]│ │
│  │ 신용평가 종합.. │ 나이스평가  │ 715 │ 🟡4등급│ 2026-04-18 │  [보기]│ │
│  │ ...(최대 10행)..│            │     │      │            │        │ │
│  └──────────────────────────────────────────────────────────────────┘ │
│                                                                        │
│                    ◀  1  2  [3]  4  5  ▶     (총 28건 · 3/3p)          │
└──────────────────────────────────────────────────────────────────────┘
```

**인터랙션**
- 검색어 입력 → 디바운스(300ms) 후 `q` 파라미터 갱신, page=1 리셋.
- 등급/기간/정렬 변경 시 해당 파라미터 갱신 + page=1 리셋.
- 페이지 변경 시 `page` 갱신(다른 조건 유지).
- 행 클릭 또는 [보기] → `/reports/[id]` 이동.
- 모든 상태 변경은 `router.replace`로 URL에 반영(히스토리 오염 방지). 자세한 규칙은 §5 참조.

**사용 컴포넌트**: `ReportFilterBar`(domain), `Table`(ui, columns/renderCell), `GradeBadge`(domain), `Pagination`(ui), `Skeleton`, `EmptyState`, `Select`, `Input`, `DateRangePicker`.

**상태**
| 상태 | 처리 |
|---|---|
| 로딩 | 테이블 행 Skeleton 10줄 / 필터 바는 유지(조작 가능) |
| 에러 | `ErrorState` + [다시 시도](refetch) 버튼 |
| 빈상태 | `EmptyState` — "조건에 맞는 리포트가 없습니다" + [필터 초기화] |

### SCR-04 · 리포트 상세 (`/reports/[id]`)

**목적**: 단일 리포트의 신용점수(게이지 시각화)·등급·발급정보를 표시하고 민감정보(주민번호 등)는 마스킹한다. 페이지 진입 시 조회 이력이 자동 기록된다.

**와이어프레임**
```
┌──────────────────────────────────────────────────────────────────────┐
│ [로고]  신용 리포트            리포트목록 | 조회이력        test@.. ▾   │
├──────────────────────────────────────────────────────────────────────┤
│  ‹ 목록으로                                                            │
│                                                                        │
│  2026 상반기 신용평가 종합 리포트                                       │
│  발급기관: KCS평가정보   |   발급일: 2026-05-02                         │
│                                                                        │
│  ┌──────────────── 신용점수 ─────────────────┐  ┌──── 신용등급 ────┐  │
│  │                                          │  │                  │  │
│  │            ╭─────────────╮               │  │       🟢         │  │
│  │         ╱                   ╲            │  │    2 등급         │  │
│  │       │       842           │           │  │   (우수)          │  │
│  │        ╲      / 1000        ╱            │  │                  │  │
│  │            ╰─────────────╯               │  └──────────────────┘  │
│  │   ░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░ 84%    │                        │
│  └──────────────────────────────────────────┘                        │
│                                                                        │
│  ┌──────────────── 기본 정보 ──────────────────────────────────────┐  │
│  │ 성명          홍 길 동                                            │  │
│  │ 주민등록번호   900101-1******        ← 마스킹                     │  │
│  │ 발급기관      KCS평가정보                                         │  │
│  │ 발급일자      2026-05-02                                          │  │
│  └──────────────────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────────────────┘
```

**인터랙션**
- 마운트 시 `GET /api/reports/{id}` 호출 → 서버가 응답 반환과 동시에 ViewHistory INSERT.
- 성공 시 `['histories']` 쿼리 invalidate → 이력 페이지 최신 반영.
- 본인 소유가 아니거나 없는 ID → 404/403 → `not-found` 폴백.
- [목록으로]는 가능하면 직전 목록 필터 URL로 복귀(브라우저 back 활용).

**사용 컴포넌트**: `CreditScoreGauge`(domain, value/max 기반), `GradeBadge`(domain), `MaskedField`(domain, 마스킹 표시), `Card`(ui), `Skeleton`, `ErrorState`.

**상태**
| 상태 | 처리 |
|---|---|
| 로딩 | 게이지·카드 영역 Skeleton |
| 에러 | 404/403 → 폴백 화면 / 5xx → `ErrorState` + 재시도 |
| 빈상태 | 해당 없음(단건 — 없으면 404 처리) |

### SCR-05 · 조회 이력 (`/history`)

**목적**: 내가 조회한 리포트 이력을 최신순으로 표시한다. 동일 리포트를 여러 번 조회한 경우 각 시점을 모두 보여주고 페이지네이션을 적용한다.

**와이어프레임**
```
┌──────────────────────────────────────────────────────────────────────┐
│ [로고]  신용 리포트            리포트목록 | 조회이력        test@.. ▾   │
├──────────────────────────────────────────────────────────────────────┤
│  조회 이력                                                             │
│                                                                        │
│  ┌──────────────────────────────────────────────────────────────────┐ │
```

## 5. URL · 쿼리파라미터 동기화 설계

목록(SCR-03)의 검색·필터·정렬·페이징 상태를 `searchParams`와 동기화하여 **새로고침·뒤로가기·URL 공유 시 동일 결과**를 보장한다. (요구사항 출처: `[02_요구사항_정의서.md]`)

### 5.1 파라미터 명세

| 파라미터 | 의미 | 타입/허용값 | 기본값 | 비고 |
|---|---|---|---|---|
| `page` | 페이지 번호 | 정수 ≥ 1 | `1` | 1-base |
| `size` | 페이지 크기 | 정수 | `10` | 고정(요구사항 10건). URL 노출 선택 |
| `q` | 검색어(제목/발급기관) | 문자열 | (없음) | 디바운스 300ms 후 반영 |
| `grade` | 신용등급 필터 | `1`~`10` | (없음) | 단일 선택. 전체면 파라미터 제거 |
| `from` | 발급일 시작 | `YYYY-MM-DD` | (없음) | `to`와 함께 기간 |
| `to` | 발급일 종료 | `YYYY-MM-DD` | (없음) | `from` 이상이어야 유효 |
| `sort` | 정렬 기준 | `issuedDate` \| `creditScore` | `issuedDate` | |
| `order` | 정렬 방향 | `asc` \| `desc` | `desc` | |

### 5.2 동기화 규칙

1. **단일 출처(SSOT)**: `useSearchParams()`가 목록 상태의 단일 진실 공급원. 별도 로컬 state로 필터를 보관하지 않는다(검색 입력만 디바운스용 임시 보유).
2. **갱신 방식**: 조건 변경 시 `router.replace(pathname?newSearchParams)` 사용 → 브라우저 히스토리 오염 방지(필터 조작마다 back 스택이 쌓이지 않음).
3. **page 리셋**: `q`/`grade`/`from`/`to`/`sort`/`order` 변경 시 `page=1`로 리셋. `page` 변경만 단독.
4. **기본값 생략**: 기본값과 동일한 파라미터는 URL에서 제거하여 깔끔한 공유 URL 유지(예: `order=desc`, `sort=issuedDate`는 생략 가능).
5. **queryKey 연동**: TanStack Query 키는 `['reports', { page, size, q, grade, from, to, sort, order }]` — searchParams 파생값을 그대로 사용해 조합별 캐싱.
6. **유효성 가드**: 잘못된 파라미터(음수 page, 비날짜 from 등)는 파싱 단계(zod)에서 기본값으로 정규화.

### 5.3 예시 URL

```
# 기본 진입 (모든 기본값 → 파라미터 없음)
/reports

# 2페이지, "KCS" 검색
/reports?page=2&q=KCS

# 2등급 + 2026-01-01~2026-06-30 기간 필터
/reports?grade=2&from=2026-01-01&to=2026-06-30

# 신용점수 오름차순 정렬 + 3페이지
/reports?sort=creditScore&order=asc&page=3

# 복합: 검색 + 등급 + 정렬 (공유/북마크 시 그대로 복원)
/reports?q=종합&grade=4&sort=issuedDate&order=desc&page=1
```

## 6. 컴포넌트 매핑

화면 ↔ 공통(ui/) / 도메인(domain/) / 레이아웃(layout/) 컴포넌트 매핑.
`ui/`는 도메인 무지(props로만 동작) → 재사용성, `domain/`은 신용평가 도메인 타입에 결합한다. (설계 출처: `[02_요구사항_정의서.md]` / 개발계획 §6)

### 6.1 화면별 사용 컴포넌트

| 화면 | 공통(ui/) | 도메인(domain/) | 레이아웃(layout/) |
|---|---|---|---|
| SCR-01 회원가입 | Input, Button, FormField, PasswordInput, Toast | — | AuthLayout |
| SCR-02 로그인 | Input, Button, FormField, PasswordInput, Alert | — | AuthLayout |
| SCR-03 목록 | Table, Pagination, Select, Input, DateRangePicker, Skeleton, EmptyState, ErrorState | ReportFilterBar, GradeBadge | ProtectedLayout, Header |
| SCR-04 상세 | Card, Skeleton, ErrorState, Button | CreditScoreGauge, GradeBadge, MaskedField | ProtectedLayout, Header |
| SCR-05 이력 | Table, Pagination, Skeleton, EmptyState, ErrorState | HistoryItem(행 렌더러) | ProtectedLayout, Header |

### 6.2 공통 컴포넌트 목록 (ui/)

| 컴포넌트 | 주요 Props(개요) | 역할 |
|---|---|---|
| `Button` | `variant`, `size`, `loading`, `disabled` | 공통 버튼(shadcn 기반) |
| `Input` | `value`, `onChange`, `error` | 텍스트 입력 |
| `PasswordInput` | `value`, `onChange`, 표시 토글 | 비밀번호 + 눈 아이콘 |
| `FormField` | `label`, `error`, `children` | 라벨+필드+에러 래퍼 |
| `Select` | `options`, `value`, `onChange` | 드롭다운(등급/정렬) |
| `DateRangePicker` | `from`, `to`, `onChange` | 발급일 기간 선택 |
| `Table` | `columns`, `data`, `renderCell` | Composition 테이블 |
| `Pagination` | `page`, `totalPages`, `onChange` | 서버 페이징 UI |
| `Card` | `children` | 정보 카드 컨테이너 |
| `Skeleton` | `count`, `variant` | 로딩 플레이스홀더 |
| `EmptyState` | `message`, `action` | 빈 상태 |
| `ErrorState` | `message`, `onRetry` | 에러 상태 + 재시도 |
| `Alert` / `Toast` | `type`, `message` | 알림 |

### 6.3 도메인 컴포넌트 목록 (domain/)

| 컴포넌트 | 주요 Props(개요) | 역할 |
|---|---|---|
| `CreditScoreGauge` | `value`, `max`(=1000), `label` | 신용점수 게이지 시각화. value/max만 받아 재사용 |
| `GradeBadge` | `grade`(1~10) | 등급별 색상 배지(목록·상세 공용) |
| `ReportFilterBar` | `params`, `onChange` | 검색·등급·기간·정렬 통합 바 |
| `MaskedField` | `label`, `maskedValue` | 마스킹 값 표시(서버에서 마스킹된 값 렌더) |
| `HistoryItem` | `history`(viewedAt, report) | 이력 행 렌더 |
| `ReportRow` | `report` | 목록 행 렌더(Table renderCell에 주입) |

### 6.4 레이아웃 컴포넌트 (layout/)

| 컴포넌트 | 역할 |
|---|---|
| `AuthLayout` | (auth) 그룹 — 중앙 정렬 카드, 헤더 없음. 인증 사용자면 /reports로 |
| `ProtectedLayout` | (protected) 그룹 — 인증 가드(미인증 시 /login), AppShell 래핑 |
| `Header` | 로고 + 네비(리포트목록/조회이력) + 계정 메뉴(로그아웃) |
| `AppShell` | 헤더 + 본문 컨테이너 공통 골격 |

## 7. 반응형 / 사용성 기본 원칙

> 과제 안내: "디자인 평가는 별도로 하지 않으나 기본 사용성은 갖출 것". 아래는 최소 사용성 기준선이다.

### 7.1 반응형 브레이크포인트 (Tailwind 기준)

| 구간 | 폭 | 레이아웃 방침 |
|---|---|---|
| 모바일 | `< 640px` (기본) | 1열. 목록 Table → 카드형 스택, 필터 바 세로 적층 |
| 태블릿 | `sm`~`md` (640~1024px) | 필터 바 2열, 테이블 유지(가로 스크롤 허용) |
| 데스크탑 | `lg ≥ 1024px` | 풀 테이블, 상세는 점수/등급 2열 그리드 |

### 7.2 사용성 원칙

1. **상태 3종 일관성**: 모든 데이터 화면은 로딩(Skeleton)·에러(ErrorState+재시도)·빈상태(EmptyState)를 공통 컴포넌트로 동일 처리.
2. **즉시 피드백**: 제출/조회 액션은 로딩 표시, 결과는 토스트/인라인으로 즉시 안내.
3. **포커스·키보드**: 폼은 Tab 순서 보장, Enter 제출. shadcn 컴포넌트의 기본 접근성(aria) 유지.
4. **명도 대비**: 등급 배지 색상은 텍스트와 충분한 대비. 색만으로 의미 전달하지 않고 숫자/라벨 병기(`🟢 2등급`).
5. **민감정보 보호**: 주민번호 등은 화면·네트워크 모두 마스킹값만 노출(서버 단계 마스킹).
6. **URL 가시성**: 목록 조건이 URL에 보이므로 새로고침·공유 시 동일 화면 재현(§5).
7. **에러 메시지 한국어**: 모든 사용자 노출 문구는 한국어. 인증 실패는 필드 특정 없이 공통 메시지(보안).
