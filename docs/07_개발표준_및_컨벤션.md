### 1.2 Backend 구조

패키지 루트는 `com.kcs.creditreport` 로 한다. 계층(layer) 기준으로 패키지를 나눈다.

```
backend/
└── src/main/java/com/kcs/creditreport/
    ├── controller/   # HTTP 진입점(REST), 요청 검증·응답 변환: Auth/Report/HistoryController
    ├── service/      # 비즈니스 로직·트랜잭션 경계: Auth/Report/HistoryService
    ├── repository/   # Spring Data JPA: User/CreditReport/ViewHistoryRepository
    ├── domain/       # JPA 엔티티+도메인 모델: User, CreditReport, ViewHistory
    ├── dto/          # 요청/응답 DTO: request/, response/
    ├── security/     # 인증·인가: JwtTokenProvider, JwtAuthenticationFilter, CustomUserDetailsService
    ├── config/       # 설정: SecurityConfig, WebConfig, OpenApiConfig
    └── common/       # 공통: exception/, response/(전역 핸들러·응답 래퍼)
└── src/main/resources/
    ├── application.yml
    └── data.sql      # H2 시드 데이터
```

> 규칙: 의존 방향은 `controller → service → repository → domain` 단방향. 역방향 의존 금지(예: domain이 service를 알지 않음).

## 3. TypeScript 표준

### 3.1 컴파일러 설정

`tsconfig.json` 에서 `strict: true` 를 활성화한다. 다음 옵션을 기본 켜짐으로 둔다.

```json
{
  "compilerOptions": {
    "strict": true,
    "noImplicitAny": true,
    "strictNullChecks": true,
    "noUnusedLocals": true,
    "noUnusedParameters": true,
    "noImplicitReturns": true,
    "forceConsistentCasingInFileNames": true
  }
}
```

### 3.2 `any` 금지 원칙

- **`any` 사용 금지** (평가 항목: 타입 안정성 / any 최소화).
- 타입을 모를 때는 `unknown` 을 사용하고 좁히기(narrowing) 후 사용한다.
- 외부 응답은 zod 스키마로 파싱하여 타입을 보장한다(`z.infer`).
- 불가피하게 `any`가 필요하면 `// eslint-disable-next-line` 주석 + 사유를 1줄로 남긴다(리뷰에서 정당성 검증).

```ts
// 나쁜 예
function parse(data: any) { return data.value; }

// 좋은 예
function parse(data: unknown): string {
  const parsed = reportSchema.parse(data); // zod 검증
  return parsed.value;
}
```

### 3.3 타입 정의 위치

| 범위 | 위치 |
|---|---|
| 여러 모듈이 공유하는 도메인 타입 | `types/` (예: `types/report.ts`) |
| 단일 컴포넌트 전용 Props | 해당 컴포넌트 파일 상단 |
| API 요청/응답 타입 | `types/api.ts` 또는 각 `lib/api/*.ts` 내부 |
| zod 추론 타입 | `lib/validators/` 에서 `z.infer`로 도출 후 export |

### 3.4 `interface` vs `type`

| 상황 | 선택 |
|---|---|
| 객체 형태(특히 Props·도메인 모델) | `interface` |
| 유니온·교차·튜플·매핑/유틸리티 타입 | `type` |
| 확장(`extends`)이 필요한 경우 | `interface` |

```ts
interface ReportCardProps {
  report: CreditReport;
  onSelect: (id: string) => void;
}

type SortOrder = "asc" | "desc";
type ReportSortKey = "issuedDate" | "creditScore";
```

## 4. Java / Spring 표준

### 4.1 패키지 구조 책임

| 계층 | 책임 | 금지 사항 |
|---|---|---|
| `controller` | HTTP 요청/응답 매핑, 입력 검증(`@Valid`), DTO 변환 | 비즈니스 로직·트랜잭션 |
| `service` | 비즈니스 로직, 트랜잭션 경계(`@Transactional`), 권한 스코프 적용 | HTTP/서블릿 의존 |
| `repository` | 데이터 접근(JPA), 동적 쿼리(Specification) | 비즈니스 분기 |
| `domain` | 엔티티·도메인 규칙 | 외부 계층 의존 |
| `dto` | 계층 간 데이터 전달 객체 | 엔티티 직접 노출 |
| `security` | 인증·인가 필터, 토큰 처리 | 도메인 로직 |
| `config` | Bean·설정 | 런타임 비즈니스 로직 |

### 4.2 DTO / Entity 분리 원칙

- **엔티티(Entity)를 컨트롤러 응답으로 직접 반환하지 않는다.** 항상 Response DTO로 변환한다.
  - 사유: 민감정보(예: password, 평문 주민번호) 노출 방지 + 직렬화 순환참조 방지 + API 계약 안정성.
- 요청은 Request DTO로 받고, `@Valid` 로 검증한다.
- 변환은 정적 팩토리 메서드(`ReportResponse.from(entity)`)로 일관화한다.

```java
// Response DTO — 마스킹·필드 선택을 응답 단계에서 수행
public record ReportResponse(
    Long id,
    String title,
    String institution,
    int creditScore,
    int creditGrade,
    LocalDate issuedDate,
    String maskedSsn          // 서버에서 900101-1****** 형태로 마스킹
) {
    public static ReportResponse from(CreditReport r) {
        return new ReportResponse(
            r.getId(), r.getTitle(), r.getInstitution(),
            r.getCreditScore(), r.getCreditGrade(), r.getIssuedDate(),
            SsnMasker.mask(r.getSsn())
        );
    }
}
```

### 4.3 계층 간 흐름 규칙

- `Pageable`·`Specification` 등 페이징·동적쿼리는 service에서 조립하여 repository에 위임한다(서버 측 처리 원칙 준수).
- 권한 검증(본인 데이터만)은 service 계층에서 `WHERE user_id = :currentUserId` 스코프를 강제한다.
- 응답 포맷은 공통 래퍼로 통일: `{ data, page, size, totalElements, totalPages }`.

## 5. 컴포넌트 작성 규칙

### 5.1 `ui/` vs `domain/` 분리 기준

| 구분 | `components/ui/` | `components/domain/` |
|---|---|---|
| 도메인 지식 | 없음(도메인 타입 import 금지) | 있음(신용평가 타입 결합) |
| 입력 | 원시 props만(`value`, `label` 등) | 도메인 객체(`report`, `history`) |
| 재사용 범위 | 프로젝트 전체·타 프로젝트 | 본 서비스 한정 |
| 예시 | `Button`, `Table`, `Gauge`, `Badge` | `CreditScoreGauge`, `GradeBadge`, `ReportCard` |

> 판단 기준: "이 컴포넌트가 신용평가 도메인 밖에서도 그대로 쓰일 수 있는가?" → 그렇다면 `ui/`, 아니면 `domain/`.

### 5.2 Props 인터페이스

- 모든 컴포넌트는 `interface 컴포넌트명Props` 를 명시한다. 인라인 익명 타입 금지.
- `any` 금지. children은 `React.ReactNode` 로 타입한다.

```tsx
interface GaugeProps {
  value: number;
  max: number;
  label?: string;
}

export function Gauge({ value, max, label }: GaugeProps) {
  const ratio = Math.min(value / max, 1);
  return (/* ... */);
}
```

### 5.3 Composition 패턴

- 도메인 컴포넌트는 `ui/` 의 범용 컴포넌트를 조합하여 만든다(상속이 아닌 합성).
- `Table` 은 `columns` + `renderCell` props로 조합형으로 설계한다(컬럼 하드코딩 금지).
- `Gauge` 는 `value/max/label` 만 받아 상세 점수와 등급 양쪽에서 재사용한다.
- 도메인 결합은 `domain/CreditScoreGauge` 가 `ui/Gauge` 를 감싸는 식으로 한 방향 합성한다.

```tsx
// domain/CreditScoreGauge.tsx — ui/Gauge를 한 방향 합성
import { Gauge } from "@/components/ui/Gauge";
import type { CreditReport } from "@/types/report";

interface CreditScoreGaugeProps {
  report: Pick<CreditReport, "creditScore">;
}
export function CreditScoreGauge({ report }: CreditScoreGaugeProps) {
  return <Gauge value={report.creditScore} max={1000} label="신용점수" />;
}
```

### 5.4 상태 UI 표준화

로딩·에러·빈 상태는 공통 컴포넌트로 일관 처리한다 — 로딩 `ui/Skeleton`, 에러 `ui/ErrorState`, 빈 결과 `ui/EmptyState`. (상태관리 평가 항목의 "로딩/에러/빈 상태 처리"와 연결)

## 6. Git 전략

### 6.1 브랜치 전략

소규모 단독 과제 특성상 경량 전략을 채택한다.

```
main                  # 항상 동작 가능한 상태 유지
 └─ feat/auth-jwt     # 기능 단위 작업 브랜치
 └─ feat/report-list
 └─ fix/refresh-loop
```

| 브랜치 | 용도 |
|---|---|
| `main` | 통합·제출 기준 브랜치 |
| `feat/*` | 신규 기능 |
| `fix/*` | 버그 수정 |
| `docs/*` | 문서 작업 |
| `refactor/*` | 동작 변경 없는 구조 개선 |

### 6.2 커밋 컨벤션

형식: `<type>: <한국어 요약>` (제목 50자 이내, 본문은 한국어로 "무엇을 왜").

| type | 용도 |
|---|---|
| `feat` | 기능 추가 |
| `fix` | 버그 수정 |
| `docs` | 문서 변경 |
| `refactor` | 리팩터링(동작 불변) |
| `style` | 포맷·세미콜론 등 비기능 변경 |
| `test` | 테스트 추가/수정 |
| `chore` | 빌드·설정·의존성 |

```
feat: 리포트 목록 서버 페이징·검색·필터 API 구현

- Pageable + JPA Specification으로 동적 쿼리 구성
- 검색(제목/기관), 등급·기간 필터, 발급일/점수 정렬 지원
- 모든 조회는 currentUserId 스코프로 권한 격리
```

> **금지 사항 (반드시 준수)**
> - **커밋 메시지에 `Co-Authored-By` 라인을 포함하지 않는다.**
> - **`.env` / 비밀키 / 토큰 시크릿을 커밋하지 않는다.** (아래 §9 참고)

### 6.3 PR 규칙

- 제목은 커밋 컨벤션과 동일 형식(`<type>: 요약`).
- 본문에 **변경 요약 / 관련 평가 항목 / 테스트 방법** 을 한국어로 기재한다.
- 자체 셀프 리뷰(린트·타입체크·빌드 통과)를 마친 뒤 머지한다.
- 단독 과제이므로 셀프 머지를 허용하되, `main` 은 항상 빌드 가능 상태를 유지한다.

## 8. 에러 처리·로깅 표준

### 8.1 Backend

- 전역 예외 처리는 `@RestControllerAdvice` 로 일원화한다.
- 응답 에러 포맷을 통일한다: `{ "code": "REPORT_NOT_FOUND", "message": "..." }` + 적절한 HTTP status.
- 도메인 예외는 의미 있는 커스텀 예외(`ReportNotFoundException` 등)로 던진다.

```java
@RestControllerAdvice
public class GlobalExceptionHandler {
    @ExceptionHandler(ReportNotFoundException.class)
    public ResponseEntity<ErrorResponse> handleNotFound(ReportNotFoundException e) {
        return ResponseEntity.status(HttpStatus.NOT_FOUND)
            .body(new ErrorResponse("REPORT_NOT_FOUND", e.getMessage()));
    }
}
```

HTTP status 기준: `400` 입력 검증 실패 · `401` 미인증·토큰 만료 · `403` 권한 없음(타인 데이터) · `404` 리소스 없음 · `409` 중복(이메일 등) · `500` 서버 오류.

- 로깅: `SLF4J` 사용. 레벨 기준 — `ERROR`(예외), `WARN`(인증 실패 등 보안 이벤트), `INFO`(주요 흐름), `DEBUG`(개발). **로그에 비밀번호·토큰·평문 주민번호를 남기지 않는다.**

### 8.2 Frontend

- 서버 에러는 TanStack Query의 `error` 상태로 받아 `ui/ErrorState` 로 일관 표시한다.
- 401은 Axios 인터셉터에서 refresh 자동 재발급으로 처리하고, 재발급 실패 시에만 `/login` 으로 보낸다(에러 표시와 분리).
- 콘솔 로그에 토큰·민감정보를 출력하지 않는다.

## 9. 환경변수 관리

### 9.1 원칙

- 비밀값(JWT 시크릿, DB 자격증명 등)은 코드에 하드코딩하지 않고 환경변수로 주입한다.
- **`.env`, `.env.local` 등 실제 값 파일은 절대 커밋하지 않는다.** `.gitignore` 에 등록한다.
- 대신 **키 목록만 담은 예시 파일**(`*.example`)을 커밋하여 협업자가 채울 수 있게 한다.

### 9.2 `.gitignore` 필수 항목

```gitignore
# 환경변수·비밀값
.env
.env.local
.env.*.local
backend/src/main/resources/application-secret.yml
# 산출물
node_modules/
.next/
build/
*.log
```

### 9.3 Frontend — `.env.local.example` (예시)

```bash
# 브라우저 노출 변수는 NEXT_PUBLIC_ 접두 필수
NEXT_PUBLIC_API_BASE_URL=http://localhost:8080/api
```

> 주의: `NEXT_PUBLIC_` 접두 변수는 클라이언트 번들에 포함되어 노출된다. **시크릿은 절대 `NEXT_PUBLIC_`으로 두지 않는다.**

### 9.4 Backend — 환경변수 예시

`application.yml` 에는 값이 아닌 **참조(`${...}`)만 커밋**하고, 실제 값은 환경변수로 주입한다.

```yaml
# application.yml — 환경변수 참조 (실제 값 미커밋)
jwt:
  secret: ${JWT_SECRET}                              # 충분히 긴 랜덤 시크릿
  access-validity-ms: ${JWT_ACCESS_VALIDITY_MS:900000}      # 기본 15분
  refresh-validity-ms: ${JWT_REFRESH_VALIDITY_MS:604800000} # 기본 7일
```

### 9.5 금지 사항 요약

| 금지 | 대안 |
|---|---|
| `.env`·비밀키 커밋 | `*.example`만 커밋, 실제값은 `.gitignore` |
| 코드에 시크릿 하드코딩 | 환경변수 참조(`${JWT_SECRET}`) |
| 시크릿을 `NEXT_PUBLIC_`에 배치 | 서버 전용 변수로 분리 |
| 로그·콘솔에 토큰/주민번호 출력 | 마스킹 또는 미출력 |
