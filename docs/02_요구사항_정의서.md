## 1. 개요 및 용어 정의

### 1.1 문서 목적

본 문서는 "개인 신용평가 리포트 조회 서비스"가 충족해야 할 **기능 요구사항(FR)** 과 **비기능 요구사항(NFR)** 을 정의하고, 각 요구사항을 고유 ID로 식별하여 과제 평가 기준 및 후속 설계 문서와 추적 가능하도록 정리하는 것을 목적으로 한다.

### 1.2 범위

- 이메일/비밀번호 기반 회원가입·로그인·로그아웃 및 JWT 인증
- 본인의 신용평가 리포트 **목록 조회**(서버 페이징·검색·필터·정렬)
- 신용평가 리포트 **상세 조회**(점수 시각화·민감정보 마스킹·조회이력 자동 기록)
- **조회 이력**(마이페이지) 관리

> 범위 제외: 실제 신용평가사 외부 API 연동(과제상 금지), 리포트 생성/편집 기능, 결제·알림 등 부가 기능.

### 1.3 평가 기준 연계

본 서비스의 요구사항은 과제 평가 기준 4개 항목과 직접 연계된다. 각 요구사항은 5장 추적 매트릭스에서 평가 기준과 매핑된다.

| 코드 | 평가 항목 | 비중 |
|---|---|:--:|
| EV-SEC | 인증·보안 구현 | 35% |
| EV-COMP | 컴포넌트 설계 및 재사용성 | 30% |
| EV-STATE | 상태관리 및 데이터 페칭 | 25% |
| EV-QUAL | 코드 품질·문서화 | 10% |

### 1.4 용어 정의

| 용어 | 정의 |
|---|---|
| **신용평가 리포트(CreditReport)** | 사용자에게 귀속된 신용점수·등급·발급기관·발급일·민감정보를 포함하는 단일 평가 결과 레코드 |
| **신용점수(credit_score)** | 0~1000 범위의 정수 신용 점수 |
| **신용등급(credit_grade)** | 1(최상)~10(최하) 범위의 등급 |
| **조회 이력(ViewHistory)** | 사용자가 특정 리포트 상세를 조회한 시점 기록. 중복 조회 시점도 각각 보존 |
| **Access Token** | 짧은 만료(15분)의 인증 토큰. FE 메모리(Zustand)에 보관, `Authorization: Bearer` 헤더로 전송 |
| **Refresh Token** | 긴 만료(7일)의 재발급용 토큰. HttpOnly + Secure + SameSite 쿠키에 보관 |
| **마스킹(Masking)** | 주민등록번호 등 민감정보를 일부 가리는 처리(예: `900101-1******`) |
| **권한 격리(Scope)** | 모든 도메인 조회 쿼리에 현재 사용자 ID 조건을 강제하여 본인 데이터만 접근 |
| **FR / NFR** | 기능 요구사항 / 비기능 요구사항 |

### 1.5 액터 정의

| 액터 | 설명 |
|---|---|
| **미인증 사용자(Guest)** | 회원가입·로그인만 가능. 보호 자원 접근 시 로그인 페이지로 리다이렉트 |
| **인증 사용자(Member)** | 로그인 완료 후 본인 리포트 목록·상세·이력 조회 가능 |
| **시스템(System)** | 토큰 발급·검증, 조회이력 자동 기록, 서버 페이징/필터링 처리 주체 |

## 2. 기능 요구사항 (FR)

> 우선순위: **필수** = 과제 명시 요구·평가 직결 / **선택** = 가산·여유 시 구현.
> ID 체계: `FR-<도메인>-<순번>` (도메인: AUTH, LIST, DETAIL, HIST).

### 2.1 인증/회원 (FR-AUTH)

| ID | 설명 | 우선순위 | 인수조건 |
|---|---|:--:|---|
| **FR-AUTH-01** | 이메일 + 비밀번호 기반 회원가입 | 필수 | 유효 이메일/정책 충족 비번 입력 시 계정 생성·201 응답 |
| **FR-AUTH-02** | 이메일 형식 검증 | 필수 | RFC 형식 위반 시 422/400, 필드 단위 에러 메시지 반환 |
| **FR-AUTH-03** | 비밀번호 정책 검증(8자 이상, 영문/숫자/특수문자 조합) | 필수 | 정책 미충족 시 가입 거부, 위반 사유 명시 |
| **FR-AUTH-04** | 이메일 중복 가입 차단 | 필수 | 기존 이메일로 가입 시 409 Conflict 반환 |
| **FR-AUTH-05** | 비밀번호 단방향 해시 저장(BCrypt) | 필수 | DB에 평문 미저장, BCrypt 해시값만 저장 |
| **FR-AUTH-06** | 로그인 시 JWT 발급(Access + Refresh 구조) | 필수 | 성공 시 Access(body) + Refresh(HttpOnly 쿠키) 발급 |
| **FR-AUTH-07** | 로그인 실패 처리 | 필수 | 이메일 불일치/비번 오류 시 401, 사유 미세분화(보안) |
| **FR-AUTH-08** | Access Token 만료 시 자동 재발급(FE 인터셉터) | 필수 | 401 감지 → `/auth/refresh` 호출 → 원요청 재시도 성공 |
| **FR-AUTH-09** | 동시 401 다발 시 refresh 단일화(큐잉) | 선택 | 중복 refresh 호출 방지, 대기 요청은 신규 토큰으로 일괄 재시도 |
| **FR-AUTH-10** | 인증 필요 페이지 접근 제어(미로그인 리다이렉트) | 필수 | 미인증 상태로 보호 경로 진입 시 `/login` 리다이렉트 |
| **FR-AUTH-11** | 로그아웃(토큰 무효화) | 필수 | Refresh 쿠키 삭제 + 서버 측 무효화, 이후 재발급 거부 |
| **FR-AUTH-12** | 새로고침 시 Access 소실 → silent 재발급 | 선택 | 앱 마운트 시 refresh로 세션 복원, 실패 시 로그인 유도 |

### 2.2 리포트 목록 조회 (FR-LIST)

| ID | 설명 | 우선순위 | 인수조건 |
|---|---|:--:|---|
| **FR-LIST-01** | 본인 리포트 목록 조회 | 필수 | 응답에 타 사용자 리포트 미포함(권한 격리) |
| **FR-LIST-02** | 서버 페이지네이션(페이지당 10건) | 필수 | `page`/`size=10` 파라미터 기반 서버 페이징, 메타(total) 반환 |
| **FR-LIST-03** | 검색: 리포트 제목 또는 발급기관명 | 필수 | `q` 파라미터로 서버 측 부분일치 검색, 클라 필터 불가 |
| **FR-LIST-04** | 필터: 신용등급(1~10등급) | 필수 | `grade` 파라미터로 서버 필터링 |
| **FR-LIST-05** | 필터: 발급일 기간(from ~ to) | 필수 | `from`/`to` 범위로 서버 필터링, 경계값 포함 |
| **FR-LIST-06** | 정렬: 발급일 / 신용점수(오름·내림차순) | 필수 | `sort`/`order` 파라미터로 서버 정렬 |
| **FR-LIST-07** | 검색·필터·정렬 상태 URL 쿼리 동기화 | 필수 | 새로고침·URL 공유 시 동일 조건 재현 |
| **FR-LIST-08** | 로딩/에러/빈 상태 처리 | 필수 | 각 상태별 전용 UI(Skeleton/ErrorState/EmptyState) 표시 |
| **FR-LIST-09** | 목록 결과 캐싱(TanStack Query) | 필수 | 필터 조합을 queryKey에 포함, staleTime/gcTime 적용 |

### 2.3 리포트 상세 조회 (FR-DETAIL)

| ID | 설명 | 우선순위 | 인수조건 |
|---|---|:--:|---|
| **FR-DETAIL-01** | 리포트 ID 기반 상세 페이지(동적 라우팅) | 필수 | `/reports/[id]` 진입 시 해당 리포트 상세 표시 |
| **FR-DETAIL-02** | 신용점수 시각화(숫자 + 그래프/게이지) | 필수 | 점수가 숫자와 게이지로 동시 표현 |
| **FR-DETAIL-03** | 신용등급 표시 | 필수 | 1~10 등급이 배지 등으로 시각 표현 |
| **FR-DETAIL-04** | 발급기관·발급일자 표시 | 필수 | 기관명·발급일 정상 노출 |
| **FR-DETAIL-05** | 민감정보 마스킹(주민번호 등) | 필수 | 서버 응답 단계 마스킹(`900101-1******`), 평문 미전송 |
| **FR-DETAIL-06** | 상세 진입 시 조회 이력 자동 기록 | 필수 | 진입마다 ViewHistory INSERT, 중복 진입도 각각 기록 |
| **FR-DETAIL-07** | 타인 리포트 ID 직접 요청 차단 | 필수 | 본인 소유 아님/미존재 시 404 또는 403 |
| **FR-DETAIL-08** | 상세 데이터 캐싱 | 선택 | 거의 불변 특성으로 staleTime 길게 설정 |

### 2.4 조회 이력 (FR-HIST)

| ID | 설명 | 우선순위 | 인수조건 |
|---|---|:--:|---|
| **FR-HIST-01** | 내가 조회한 리포트 목록 최신순 표시 | 필수 | `viewed_at DESC` 정렬로 노출 |
| **FR-HIST-02** | 동일 리포트 중복 조회 시점 모두 기록 | 필수 | 같은 리포트의 여러 조회 시각이 각각 행으로 표시 |
| **FR-HIST-03** | 조회 이력 페이지네이션 | 필수 | 서버 페이징 적용, 페이지 이동 동작 |
| **FR-HIST-04** | 본인 이력만 조회(권한 격리) | 필수 | 타 사용자 이력 미포함 |
| **FR-HIST-05** | 이력 페이지 항상 최신 반영 | 필수 | 상세 진입 후 이력 페이지 진입 시 최신 기록 반영(invalidate) |

> **FR 요약**: 인증/회원 12 + 리포트 목록 9 + 리포트 상세 8 + 조회 이력 5 = **총 34개**

## 3. 유스케이스

### UC-01. 회원가입 및 로그인

| 항목 | 내용 |
|---|---|
| **관련 FR** | FR-AUTH-01~07, FR-AUTH-10 |
| **액터** | 미인증 사용자(Guest) |
| **사전조건** | 미로그인 상태, 가입 화면 접근 가능 |

**기본 흐름**
1. 사용자가 회원가입 화면에서 이메일·비밀번호를 입력한다.
2. 클라이언트가 이메일 형식·비밀번호 정책을 1차 검증한다.
3. 서버가 동일 검증을 재수행하고 비밀번호를 BCrypt로 해시하여 계정을 생성한다(201).
4. 사용자가 로그인 화면에서 자격증명을 입력한다.
5. 서버가 인증에 성공하면 Access(body) + Refresh(HttpOnly 쿠키)를 발급한다.
6. 클라이언트가 Access를 메모리에 보관하고 리포트 목록(`/reports`)으로 리다이렉트한다.

**예외 흐름**
- 2a/3a. 이메일 형식 위반 → 422/400, 필드 에러 표시.
- 3b. 비밀번호 정책 미충족 → 위반 사유 표시 후 가입 차단.
- 3c. 이메일 중복 → 409, "이미 가입된 이메일" 안내.
- 5a. 자격증명 불일치 → 401, 일반화된 로그인 실패 메시지.

---

### UC-02. 리포트 목록 검색·필터·정렬 조회

| 항목 | 내용 |
|---|---|
| **관련 FR** | FR-LIST-01~09 |
| **액터** | 인증 사용자(Member) |
| **사전조건** | 로그인 완료, 유효 Access 보유 |

**기본 흐름**
1. 사용자가 `/reports`에 진입한다.
2. 클라이언트가 현재 URL 쿼리(page/q/grade/from/to/sort/order)를 읽어 목록을 요청한다.
3. 서버가 현재 사용자 ID 스코프 내에서 페이징·검색·필터·정렬을 처리해 결과 + 메타를 반환한다.
4. 사용자가 검색어·등급·기간·정렬을 변경한다.
5. 클라이언트가 변경 조건을 URL 쿼리에 동기화하고 재조회한다.
6. 화면에 페이지당 10건이 표시되고 페이지 이동이 가능하다.

**예외 흐름**
- 2a. Access 만료 → 인터셉터가 401 감지 → refresh 후 원요청 재시도(FR-AUTH-08).
- 3a. 조건에 맞는 결과 없음 → EmptyState 표시.
- 3b. 서버 오류 → ErrorState + 재시도 제공.

---

### UC-03. 리포트 상세 조회 및 이력 자동 기록

| 항목 | 내용 |
|---|---|
| **관련 FR** | FR-DETAIL-01~07, FR-HIST-02, FR-HIST-05 |
| **액터** | 인증 사용자(Member) |
| **사전조건** | 로그인 완료, 목록에서 리포트 선택 |

**기본 흐름**
1. 사용자가 목록에서 특정 리포트를 선택해 `/reports/[id]`로 이동한다.
2. 서버가 본인 소유 여부를 확인하고 상세를 반환한다(민감정보는 마스킹 적용).
3. 동시에 시스템이 ViewHistory에 조회 시점을 INSERT한다.
4. 클라이언트가 신용점수 게이지·등급 배지·발급정보·마스킹 데이터를 렌더링한다.
5. 성공 시 `['histories']` 캐시를 invalidate하여 이력 페이지 최신화를 예약한다.

**예외 흐름**
- 2a. 타인 소유/미존재 ID → 404 또는 403, 접근 차단 화면.
- 2b. Access 만료 → refresh 후 재시도.

---

### UC-04. 조회 이력 확인 (마이페이지)

| 항목 | 내용 |
|---|---|
| **관련 FR** | FR-HIST-01~05 |
| **액터** | 인증 사용자(Member) |
| **사전조건** | 로그인 완료, 1건 이상 상세 조회 이력 존재(없으면 빈 상태) |

**기본 흐름**
1. 사용자가 `/history`에 진입한다.
2. 서버가 본인 이력을 `viewed_at DESC` + 페이징으로 반환한다.
3. 화면에 최신순 이력이 표시되고, 동일 리포트의 중복 시점도 각각 노출된다.
4. 사용자가 페이지를 이동하며 과거 이력을 확인한다.

**예외 흐름**
- 2a. 이력 없음 → EmptyState 표시.
- 2b. Access 만료 → refresh 후 재시도.

## 4. 비기능 요구사항 (NFR)

> ID 체계: `NFR-<범주>-<순번>` (범주: SEC 보안, PERF 성능, USA 사용성, MNT 유지보수성, COMPAT 호환성).

### 4.1 보안 (NFR-SEC) ★ 최우선(평가 35%)

| ID | 설명 | 검증 기준 |
|---|---|---|
| **NFR-SEC-01** | Access/Refresh 토큰 분리 전략 | Access 15분(메모리) / Refresh 7일(HttpOnly 쿠키) |
| **NFR-SEC-02** | Access 토큰 저장 위치 — XSS 노출면 최소화 | localStorage 미사용, 메모리(Zustand)만 보관 |
| **NFR-SEC-03** | Refresh 토큰 JS 접근 차단 | HttpOnly + Secure + SameSite 쿠키, JS 비노출 |
| **NFR-SEC-04** | CSRF 대응 | Refresh 쿠키 SameSite=Strict/Lax + 상태변경 API는 Bearer 헤더 인증 |
| **NFR-SEC-05** | 비밀번호 단방향 해싱 | BCrypt 적용, 평문/가역 암호화 미사용 |
| **NFR-SEC-06** | 민감정보 마스킹(서버 단계) | 주민번호 등 평문이 네트워크로 미전송, 마스킹 형식 일관 |
| **NFR-SEC-07** | API 권한 검증(본인 데이터만) | 모든 도메인 쿼리에 사용자 ID 스코프 강제, 타인 자원 404/403 |
| **NFR-SEC-08** | 라우트 보호(FE/BE 이중) | FE 미인증 리다이렉트 + BE SecurityFilterChain 인증 요구 |
| **NFR-SEC-09** | 비밀키 환경변수 관리 | JWT 시크릿 등 `.env` 분리, 저장소 커밋 금지 |
| **NFR-SEC-10** | XSS 입력/출력 안전 | 사용자 입력 이스케이프, dangerouslySetInnerHTML 미사용 원칙 |
| **NFR-SEC-11** | 토큰 무효화(로그아웃) | Refresh 무효화 후 재발급 시도 거부 |
| **NFR-SEC-12** | 서버 측 처리 강제 | 페이징·검색·필터·정렬을 서버에서 처리(클라 단순 필터 불인정) |

## 6. 데이터 요구사항 요약

> 상세 스키마·제약·시드는 `[04_데이터베이스_설계서.md]` 참조.

### 6.1 핵심 엔티티

| 엔티티 | 핵심 속성 | 관계 |
|---|---|---|
| **User** | id(PK), email(unique), password(BCrypt), created_at | User 1 — N CreditReport, User 1 — N ViewHistory |
| **CreditReport** | id(PK), user_id(FK), title, institution, credit_score(0~1000), credit_grade(1~10), issued_date, ssn(마스킹 대상) | CreditReport 1 — N ViewHistory |
| **ViewHistory** | id(PK), user_id(FK), report_id(FK), viewed_at | 상세 진입마다 INSERT |

### 6.2 데이터 규칙

| 항목 | 규칙 | 관련 요구사항 |
|---|---|---|
| 이메일 유일성 | User.email UNIQUE 제약 | FR-AUTH-04 |
| 비밀번호 저장 | BCrypt 해시만 저장(평문 금지) | FR-AUTH-05, NFR-SEC-05 |
| 권한 격리 | 모든 조회에 `WHERE user_id = :currentUserId` | FR-LIST-01, FR-DETAIL-07, FR-HIST-04, NFR-SEC-07 |
| 이력 누적 | 중복 조회 시점도 각각 INSERT | FR-DETAIL-06, FR-HIST-02 |
| 마스킹 | 민감정보는 서버 응답 단계에서 마스킹 | FR-DETAIL-05, NFR-SEC-06 |
| 시드 데이터 | 테스트 계정 1개 + 리포트 25~30건(등급/발급일 분산) | NFR-COMPAT-02 |
