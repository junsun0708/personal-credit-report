## 1. 개요

| 구분 | 값 |
|---|---|
| 총 예상 공수 | **9.0h** (과제 안내 8~10h 범위 내, 중앙값 기준 산정) |
| 제출 기한 | 과제 안내일로부터 **7일 이내** |
| 제출물 | GitHub Public Repository URL (커밋 히스토리 포함) 또는 `이름_KCS_과제.zip` |
| 작업 단위 | 본 문서는 마일스톤 M1~M7(개발계획서 기준) + 문서화(M0) + 마감(M7) 으로 분해 |

### 1.1 공수 산정 근거
- 과제 안내서 "예상 소요 시간 8~10시간"의 중앙값 9.0h를 기준선으로 채택한다.
- 평가 비중(인증·보안 35% > 컴포넌트 30% > 상태관리 25% > 코드품질·문서화 10%)에 비례하여 공수를 배분한다.
- 문서화(M0)는 착수 전 설계 기준선 수립용으로, 코딩 9.0h와 별도로 병렬 진행한다.

### 1.2 작업시간 기록(타임시트) 정산 방식
- 과제 제출 시 **실제 투입 시간**을 기록·정산해야 하므로, 각 작업 착수/종료 시각을 §8 양식에 기록한다.
- 예상 공수 대비 실투입 편차(Variance)를 함께 기록하여 README 회고의 "시간 부족 미구현 사유" 근거로 활용한다.
- 일자별 누적 투입 시간을 §5 간트 차트의 실적(Actual)란에 갱신한다.

## 4. 작업 순서 / 의존성

### 4.1 의존성 그래프 (ASCII)

```
                M0 문서화 (설계 기준선, 코딩과 병렬·선행)
                     │ (설계 산출물이 모든 코딩의 입력)
                     ▼
  ┌──────────────── BE 트랙 ────────────────┐
  │                                          │
  M1 BE환경 ──▶ M2 BE인증 ──▶ M3 BE도메인API │
  (엔티티/시드)  (Security/JWT)  (목록/상세/이력)
                     │                 │
                     │ (인증 계약 확정)│ (API 계약 확정)
                     ▼                 ▼
  ┌──────────────── FE 트랙 ────────────────┐
  M4 FE토대 ──▶ M5 FE인증 ──▶ M6 FE도메인화면│
  (인터셉터/스토어)(로그인/보호) (목록/상세/이력)
                                       │
                                       ▼
                         M7 테스트·마감 (전 트랙 통합 후)
```

### 4.2 선후관계 표

| 작업 | 선행(Predecessor) | 사유 |
|---|---|---|
| M1 BE환경 | M0 (설계) | ERD·엔티티 설계가 입력 |
| M2 BE인증 | M1 | 엔티티(User)·Security 의존성 필요 |
| M3 BE도메인API | M1, M2 | 엔티티 + 인증 컨텍스트(현재 사용자) 필요 |
| M4 FE토대 | M0 | API 계약 확정 후 인터셉터 설계 가능 |
| M5 FE인증 | M2, M4 | BE 인증 API 계약 + 인터셉터 토대 필요 |
| M6 FE도메인화면 | M3, M5 | BE 도메인 API + FE 인증(보호 라우트) 필요 |
| M7 마감 | M5, M6 | 전 기능 통합 후 검증·문서화 |

> 핵심 임계경로(Critical Path): **M0 → M1 → M2 → M3 → M6 → M7**.
> M4(FE토대)는 M1과 병렬 착수 가능하나, 단독 작업 환경이므로 BE 우선 직렬 진행을 권장(인증 계약 안정 후 FE).
