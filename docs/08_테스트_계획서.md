## 1. 테스트 개요 · 목표 · 범위

### 1.1 목적

본 문서는 개인 신용평가 리포트 조회 서비스의 품질을 검증하기 위한 테스트 전략·범위·케이스를 정의한다. 특히 평가 비중이 가장 높은 **인증·보안(35%)** 영역을 우선 검증하여, 본인 데이터만 조회되는 권한 격리와 토큰 전략의 정합성을 보장하는 데 초점을 둔다.

### 1.2 테스트 목표

| 목표 ID | 목표 | 연관 평가항목 |
|---|---|---|
| G-1 | 인증·인가 흐름(회원가입·로그인·재발급·권한격리)의 정확성 검증 | 보안 35% |
| G-2 | 서버 측 페이징·검색·필터·정렬 동작 및 URL 동기화 검증 | 상태관리 25% |
| G-3 | 민감정보 마스킹·조회이력 기록의 정확성 검증 | 보안 35% / 컴포넌트 30% |
| G-4 | 로딩·에러·빈 상태 등 UI 상태 처리의 일관성 검증 | 상태관리 25% / 컴포넌트 30% |
| G-5 | 타입 안정성·핵심 회귀 방지 최소 테스트 확보 | 품질 10% |

### 1.3 테스트 범위

**포함 (In-Scope)**
- 인증 도메인: 회원가입 입력 검증, 로그인, Access/Refresh 토큰 발급·재발급·로그아웃, 권한 격리
- 리포트 목록: 서버 페이징, 검색, 필터(등급·기간), 정렬, URL 쿼리 동기화
- 리포트 상세: 점수/등급 표현, 민감정보 마스킹, 조회 이력 자동 기록
- 조회 이력: 최신순 정렬, 중복 조회 시점 모두 기록, 페이징
- 보안 횡단 항목: 타인 데이터 접근 차단, 토큰 만료/위조, XSS/CSRF 관점

**제외 (Out-of-Scope)** — 상세 사유는 §8 참조
- 성능/부하 테스트, 대규모 동시성 테스트
- 크로스 브라우저 매트릭스 전수 테스트
- 디자인/시각 회귀(VRT) — 과제상 디자인 평가 제외
- 외부 신용평가사 API 연동(과제상 외부 API 사용 불가)

### 1.4 우선순위 원칙 (8~10시간 제약 반영)

테스트 작성 공수는 한정되므로 아래 순으로 배분한다. 평가 비중과 일치시킨다.

```
P0 (필수)  인증·보안·권한격리·마스킹  ──► 평가 35%
P1 (높음)  목록 서버처리·URL동기화·이력 기록  ──► 평가 25%
P2 (보통)  상세 시각화·상태 UI(로딩/에러/빈)  ──► 평가 30%
P3 (낮음)  부가 UX·예외 케이스 보강  ──► 여유 시
```

> **전략 결론**: 자동화 테스트는 **P0 백엔드 단위/통합**에 집중하고, FE는 핵심 훅·유틸 단위 테스트 + 최소 E2E 스모크만 작성한다. 나머지는 수동 검증 체크리스트(§3 표의 우선순위 컬럼)로 커버한다.

## 2. 테스트 전략

### 2.1 테스트 레벨 (테스트 피라미드)

| 레벨 | 비중(목표) | 대상 | 비고 |
|---|:--:|---|---|
| 단위 (Unit) | 60% | 마스킹 유틸, 비밀번호 검증, JWT 생성/검증, 권한 스코프, FE 훅/유틸 | 빠르고 결정적. 최우선 |
| 통합 (Integration) | 30% | Controller↔Service↔Repository, Security Filter Chain, 동적 쿼리 페이징 | `@SpringBootTest` / `MockMvc` |
| E2E | 10% | 로그인→목록→상세→이력 핵심 해피패스 스모크 | Playwright 최소 시나리오 |

### 2.2 영역별 도구

| 영역 | 레벨 | 도구 | 적용 범위 |
|---|---|---|---|
| Backend | 단위 | **JUnit 5 + AssertJ + Mockito** | 마스킹/검증/토큰/권한 로직, Service 단위 |
| Backend | 통합 | **Spring Boot Test + MockMvc** (+ `@DataJpaTest`) | API 엔드포인트, Security, JPA 동적쿼리·페이징 |
| Backend | 보안 | **spring-security-test** (`@WithMockUser` 등) | 인증 컨텍스트, 권한 격리 |
| Frontend | 단위 | **Vitest + React Testing Library** | 마스킹 표시, queryKey 유틸, URL 동기화 훅, 폼 검증(zod) |
| Frontend | 컴포넌트 | **Vitest + RTL** | 상태 UI(로딩/에러/빈), Pagination, GradeBadge, Gauge |
| Frontend | E2E | **Playwright** | 인증→목록→상세→이력 스모크, 보호 라우트 리다이렉트 |

> Vitest를 기본으로 하되, 프로젝트 초기화가 Jest로 구성될 경우 동일 테스트를 Jest + RTL로 대체한다(API 호환). 본 계획은 도구 종속이 아닌 검증 의도를 기준으로 한다.
